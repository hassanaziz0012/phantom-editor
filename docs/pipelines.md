# 🎬 Content & Video Processing Pipelines

The **Pipelines** module provides an end-to-end orchestration suite for creating, processing, tracking, and scheduling YouTube videos. It automates the multi-stage lifecycle from initial project creation, Excalidraw scripting, and single-pass FFmpeg editing to quality review, metadata authoring, Google Sheets project synchronization, and publishing.

---

## 🛠️ CLI Quick Reference

All pipeline subcommands are accessible via the `phantom pipeline` CLI:

```bash
# Check status and overview of all YouTube projects
phantom pipeline status

# Create a brand new YouTube video project workspace
phantom pipeline newvideo "My New Video Title"

# Run automated video processing (transcription, masking, silence trim, audio cleanup, BGM)
phantom pipeline process /path/to/webcam.mp4 /path/to/screen.mp4 --bgm lofi-chill

# Process a pre-composed raw video (skips webcam masking; trims silences directly)
phantom pipeline process --raw /path/to/raw.mp4 --bgm lofi-chill
```

### The Pipeline Stages

| Stage | Name | Trigger / File Requirements | Next Action Required |
| :---: | :--- | :--- | :--- |
| **1** | **New** | Newly created folder, missing the `.excalidraw` script or a filled-in `outline.md`, and no raw footage. | Create `.excalidraw` presentation script and `outline.md`. |
| **2** | **Scripted** | Contains `.excalidraw` script file and an `outline.md` whose `# Hook` and `# Outline` sections both have text, and which contains a `[LIKE / SUBSCRIBE]` marker where the video asks viewers to engage. | Record raw webcam and screen footage. |
| **3** | **Recorded** | Raw video files present, no `to-review.mp4`. | Run `phantom pipeline process`. |
| **4** | **Processed** | `to-review.mp4` generated by pipeline. | Review video and export `final.mp4`. |
| **5** | **Reviewed** | `final.mp4` exists; missing metadata/thumbnail. | Create `metadata.json` and design thumbnail. |
| **6** | **Added Metadata** | `final.mp4` + `metadata.json` present; missing thumbnail. | Design and add thumbnail image. |
| **7** | **Added Thumbnail** | `final.mp4` + thumbnail present; missing `metadata.json`. | Create `metadata.json`. |
| **8** | **Ready to Schedule** | `final.mp4` + `metadata.json` + thumbnail image present. | Ready for YouTube upload (`phantom yt upload`) or set publishDate in `metadata.json`. |
| **9** | **Scheduled** | Has scheduled publish date in `metadata.json`. | Upload video to YouTube (`phantom yt upload`). |
| **10** | **Uploaded** | `metadata.json` contains a valid YouTube URL. | 🎉 Pipeline complete! |
| **11** | **Needs Repackaging** | 48h after publish, its first 2 days' CTR was below the channel's 28-day CTR. | Rework the title & thumbnail on YouTube. |

### 48h Performance Check

Once an uploaded video has been public for 48 hours, `status` reads its analytics live from YouTube Studio (through the logged-in Chrome on port 9222, like `phantom yt info`) and stores them in `metadata.json` under `performanceCheck`, along with the full `yt info` payload. The check runs once per video; later runs use the stored result, so `status` stays instant.

The video's CTR over its first 2 Pacific-time days since publish (the publish day and the day after) is compared with the channel's long-form CTR over the last 28 days, the number on the Videos card of Studio's Content tab (see `phantom yt channel-stats`). If it's lower, the video moves to **Needs Repackaging**. Impressions, views, and average view duration are stored on both sides for reference, under `video` and `channel_28d`. The video's average view duration is Studio's since-publish figure at check time, since Studio's average isn't simply watch time divided by views and can't be recomputed for the 2-day window. Shorts aren't checked, since the channel stats cover long-form videos.

While a video needs repackaging, every `status` run compares its live YouTube title with the `metadata.json` title and its live thumbnail with every local `thumbnail*` image (by perceptual hash, since YouTube re-encodes thumbnails). Once either differs, the change is recorded under `performanceCheck.repackaged` and the video goes back to **Uploaded**. So when you repackage, change the title and thumbnail on YouTube but leave `metadata.json` and the local thumbnails as the originals. To run the check again, delete the `performanceCheck` key. See `youtube_api/performance_check.py`.

## ⚡ Video Processing Engine: `projects/process_video.py`

`phantom projects process` runs a 7-step pipeline that turns raw footage into `final.mp4`, reviews it automatically, generates `metadata.json`, and writes a `summary.md` run report. The code lives in the `projects/pipeline/` package; `process_video.py` is only the entry point.

It operates in two modes:
* **Webcam Mode** (`<webcam> [screen]`): Overlays a rounded webcam mask on the screen recording (toggled by `"webcam start"` / `"webcam stop"` voice commands, or always with `--all`) and trims silences in one FFmpeg pass.
* **Raw Mode** (`--raw <raw_video>`): Trims silences directly from a pre-composed recording. Only the speech audio is extracted up front; the video is encoded once, at the end, straight from the source.

### Pipeline Steps

| # | Step | Raw mode | Webcam mode |
| :--- | :--- | :--- | :--- |
| 1 | Transcription (`transcribe_cloud.py`) | Background thread | Background with `--all`, otherwise before Step 2 (voice commands need the captions) |
| 2 | Silence trim | Silero VAD + audio-only extraction -> `raw-audio.wav` | Webcam mask + silence trim -> `after-trim-silences.mp4` |
| 3 | Audio processing (`process_audio.sh`) | DeepFilterNet + loudnorm -> `processed-audio.wav` | same |
| 4 | Final output | Single-pass encode + mux (+ BGM mixed inline, black-frame QC inline) -> `final.mp4` | Remux processed audio (+ BGM via `add_bgm_to_video.sh`) -> `final.mp4` |
| 5 | Verify | Structural check that `final.mp4` is not truncated or stuck on one frame | same |
| 6 | Review (`audio_review.py`, `video_inspector.py`) | Audio review only (black frames were checked in Step 4) | Audio review + video inspector |
| 7 | Metadata (`auto_create_metadata.py`) | Transcribes `final.mp4` -> `trimmed.srt`, then generates everything from it; background thread, overlapping Step 6 | same |

### Manual Cuts (Raw Mode)

To cut bad takes, put a `cuts.txt` next to the raw video with one `START-END` range per line, on the raw recording's timeline (`MM:SS` or `HH:MM:SS`, fractional seconds allowed, `#` comments ignored):

```text
02:05-02:17
06:30-06:37.5
```

The ranges are removed from the speech intervals before Steps 2 and 4 cut, so they cost no extra encode. They are listed in the pre-run overview and in `summary.md`. A malformed line stops the run before anything is processed. All metadata (description, tweet, chapters) is generated from `trimmed.srt`, so cut takes never reach it.

### Smart Resumption

A step is skipped when its output file already exists and is valid. In raw mode, Step 2 also re-runs when `cuts.txt` is newer than `raw-audio.wav`. Once any step really runs, every later step re-runs too, since its inputs changed. The review (Step 6) runs only when something upstream ran. Pass `--force` to re-run everything.

### Code Layout (`projects/pipeline/`)

| Module | Responsibility |
| :--- | :--- |

## 🔌 Google Sheets Backend: [`google_sheet_utils.py`](file:///home/hassan/Desktop/programming/phantom-editor/pipelines/google_sheet_utils.py)

The backend driver powering Google Sheets synchronization:

* **Google Service Account Authentication**: Authenticates securely and permanently using headless Google Cloud Service Account credentials (`GOOGLE_SERVICE_ACCOUNT_EMAIL` and `GOOGLE_PRIVATE_KEY`), eliminating the need for expiring user tokens or interactive browser logins.
* **Dynamic Header & Schema Mapping**: Detects existing sheet headers (`Title`, `Description`, `URL`, `Publish Date`, `Platform`) or initializes default columns if the sheet is empty.
* **Default Worksheet**: Synchronizes with the `YouTube` sheet tab by default.
* **Project Synchronization**: One-way sync from local project folders to the sheet via `sync_projects_to_sheet()` during `phantom pipeline status`.
* **Written Content Synchronization**: [`written_content_sheet_utils.py`](file:///home/hassan/Desktop/programming/phantom-editor/pipelines/written_content_sheet_utils.py) re-exports sheet utilities for tracking written social posts across platforms (Substack, LinkedIn).

### Configuration

Ensure your `.env` file contains your Google Service Account credentials and Google Sheet ID:

```bash
GOOGLE_SERVICE_ACCOUNT_EMAIL=your-service-account@<project>.iam.gserviceaccount.com
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
CONTENT_CALENDAR_SHEET_ID=your_google_sheet_id_here
```

> [!NOTE]
> Make sure the target Google Sheet is shared with `GOOGLE_SERVICE_ACCOUNT_EMAIL` as an **Editor**.
